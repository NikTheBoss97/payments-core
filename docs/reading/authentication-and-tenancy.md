# Authentication and tenant isolation

API keys, signed messages, least privilege, object-level authorization and row-level security. Part of the [reading list](README.md).

- ★ OWASP, [API1:2023 Broken Object Level Authorization](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization) (OWASP API Security Top 10, 2023). The top API risk: an endpoint trusts an object's ID from the client, so one forgotten check exposes another customer's data.
- ★ PostgreSQL, [5.9. Row Security Policies](https://www.postgresql.org/docs/18/ddl-rowsecurity.html) (PostgreSQL 18 docs). Default deny, who bypasses a policy, why foreign-key checks always do, and the covert channels and races to watch for.
- AWS, [Row-level security recommendations](https://docs.aws.amazon.com/prescriptive-guidance/latest/saas-multitenant-managed-postgresql/rls.html) (AWS Prescriptive Guidance). Row-level security as the way to keep tenants apart when they share one database and one schema.
- PostgreSQL, [CREATE POLICY](https://www.postgresql.org/docs/18/sql-createpolicy.html) (PostgreSQL 18 docs). Permissive policies combine with `OR` and restrictive ones with `AND`, so a restrictive policy can only narrow what a permissive one allows.
- NIST, [SP 800-63B-4: Digital Identity Guidelines: Authentication and Authenticator Management](https://pages.nist.gov/800-63-4/sp800-63b.html) (2025). Section 3.1.2.2 draws the line that decides how a secret is stored: at 112 bits and above, an approved hash is enough, and below that it takes a salted password hashing scheme.
- NIST, [Least privilege](https://csrc.nist.gov/glossary/term/least_privilege) (CSRC glossary). Today's definitions of the principle, from SP 800-53 Rev. 5 and SP 800-171r3: each entity gets the minimum authorizations that its function needs.
- A. Backman, J. Richer and M. Sporny, [RFC 9421: HTTP Message Signatures](https://www.rfc-editor.org/rfc/rfc9421) (IETF, 2024). Signing chosen parts of an HTTP message; its section on canonicalization attacks explains why "Any ambiguity in the generation of the signature base" gives an attacker leverage.
- M. Jones and D. Hardt, [RFC 6750: The OAuth 2.0 Authorization Framework: Bearer Token Usage](https://www.rfc-editor.org/rfc/rfc6750.html) (IETF, 2012). The `Authorization: Bearer` header, the 401 and `WWW-Authenticate` that answer a bad token, and why a bearer token needs TLS.
- H. Krawczyk, M. Bellare and R. Canetti, [RFC 2104: HMAC: Keyed-Hashing for Message Authentication](https://www.rfc-editor.org/rfc/rfc2104) (IETF, 1997). The HMAC construction, and why a key shorter than the hash's output is "strongly discouraged".
- Wen Zhang, Eric Sheng, Michael Chang, Aurojit Panda, Mooly Sagiv and Scott Shenker, [Blockaid: Data Access Policy Enforcement for Web Applications](https://www.usenix.org/conference/osdi22/presentation/zhang) (OSDI, 2022). Enforcing data-access policy at the boundary between a web application and its database, on the premise that checks scattered through application code get missed.
- Tom Van Goethem, Christina Pöpper, Wouter Joosen and Mathy Vanhoef, [Timeless Timing Attacks: Exploiting Concurrency to Leak Secrets over Remote Connections](https://www.usenix.org/conference/usenixsecurity20/presentation/van-goethem) (USENIX Security, 2020). Concurrent requests over HTTP/2 take network jitter out of a timing attack, and expose differences "as small as 100ns".
- Mihir Bellare, [New Proofs for NMAC and HMAC: Security without Collision Resistance](https://doi.org/10.1007/s00145-014-9185-x) (Journal of Cryptology, 2015). Why HMAC's security does not rest on its hash being collision-resistant.
- Scott A. Crosby, Dan S. Wallach and Rudolf H. Riedi, [Opportunities and Limits of Remote Timing Attacks](https://doi.org/10.1145/1455526.1455530) (ACM TISSEC, 2009). Measuring time "with 15-100µs accuracy across the Internet, and as good as 100ns over a local network": why a secret is compared in constant time.
- Shariq Rizvi, Alberto Mendelzon, S. Sudarshan and Prasan Roy, [Extending Query Rewriting Techniques for Fine-Grained Access Control](https://doi.org/10.1145/1007568.1007631) (SIGMOD, 2004). An early case for enforcing per-row access control inside the database rather than in each application, through query rewriting.
- Martín Abadi and Roger Needham, [Prudent Engineering Practice for Cryptographic Protocols](https://doi.org/10.1109/32.481513) (IEEE Transactions on Software Engineering, 1996). Its first principle, "Every message should say what it means", so that one signed message cannot be read as another.
- J. H. Saltzer and M. D. Schroeder, [The Protection of Information in Computer Systems](https://doi.org/10.1109/PROC.1975.9939) (Proceedings of the IEEE, 1975). The eight design principles, among them least privilege, which "limits the damage that can result from an accident or error".
